# 文件tail观察者偏移越过未写完半行致事件在实时流永久漏推

## 背景 / 现象

观测面板实时流(SSE)由 watcher 线程轮询 `traces/*.jsonl` 增量读取实现(文件 size 变了就
seek 到上次偏移读新内容)。第十二轮走查实测: 写方把一行分两次写(两段之间恰好被 watcher
轮询读到), 该事件在 SSE 实时流里**永久不出现**, 但 JSONL 文件本身完整、刷新页面后能在
历史流里看到——"实时漏一条, 刷新又回来了", 极易被当成偶发误判。

## 根因

经典 tail 缺陷: 读到 chunk 后**无条件把偏移推进到 chunk 末尾**, 而 JSON 行解析失败只
`continue` 吞掉。半行(未写完的行)必然 JSONDecodeError → 被吞, 但偏移已越过这些字节;
下次轮询时行已补全, 却整体位于偏移之前 → 永远不再被读到。等价于"把一次读到什么和消费
了什么混为一谈"。

## 解决方案

tail 语义: **只消费到最后一个换行符**, 偏移停在行边界, 半行留给下次轮询。

```python
with f.open("rb") as fh:
    fh.seek(pos); chunk = fh.read()
cut = chunk.rfind(b"\n")
if cut < 0:
    continue                      # 没有完整行, 偏移原地不动
self._offsets[f] = pos + cut + 1  # 停在行边界
for ln in chunk[:cut].decode("utf-8", "replace").splitlines():
    ...
```

两个口径细节: ①改**二进制读**——`st_size`、偏移、截断检测(`size < pos` 重置)必须同为
字节口径, 文本模式 `tell()` 是 opaque cookie 不可手工推进; ②`\n`(0x0A)不会出现在
UTF-8 多字节序列内部(后续字节恒 ≥0x80), 按换行截断后整行解码必合法; CRLF 的 `\r` 随
`splitlines()` 剥掉。

## 验证

探针实测(分两段写一行, 段间 sleep 让 watcher 轮询落在中间): 修复前 SSE 只收到后续完整
事件 tail-B, 半行事件 tail-A 永久漏推(文件里 tail-A 行数=1, 完整); 修复后 tail-A/tail-B
都实时到达。回归 `test_watcher_waits_for_complete_line`(直接驱动 `_tick`: 半行不消费→
补全后广播一次→再 tick 不重复), pytest 286 全绿。

## 适用边界与反例

适用于一切"轮询 tail 文件 + 增量偏移"的观察者(自研 tail -F、日志采集 agent、watcher
线程)。判据: 只要写方不保证单次原子写完整行(OS 可拆写、跨进程可交错), 观察者就必须按
行边界对齐消费。反例: 单行短追加且平台保证原子(如 Linux PIPE_BUF 内的 pipe)可简化,
但文件追加没有任何平台保证。与"坏行"区分: 真正永久损坏的行(换行前就非法 JSON)按行边界
消费一次后跳过是对的, 不该无限重读——区分标准是行尾**有没有换行符**, 有=完整可判定,
没有=还没写完。
