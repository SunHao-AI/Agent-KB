# 动画轨道几何须对准内容实际bbox且目标参数突变须缓动

## 背景 / 现象
prompt-spider-ui 词墙回放中蜘蛛绕椭圆轨道巡游, 两个先后问题:
1. 轨道对准"名义区域"(wallArea)而非词团实际位置, 事件少时词团紧凑在顶部而蜘蛛绕大区域中心转, 像在空处转圈(测试文档 §16)。
2. 改为对准实际 bbox(`tightBox`)后引入新突跳: 首词到达(0→1 个词)、翻页、路由过滤使 bbox 瞬时改变, 椭圆中心/半径一步换值, 蜘蛛从区域中心"瞬移"到词团中心(目测 250px 级一步到位), 观感突兀(§17 前现象, 用户截图证实)。

## 根因
两个机制层原因:
1. **名义区域 ≠ 内容实际几何**: 数据驱动的布局区域随事件数伸缩(行高/间距若不封顶还会被拉伸), 任何对准固定名义区域的动画几何在数据变化时必错位。
2. **解析轨道对 time 连续, 但轨道参数本身不连续**: `angle=time*ω` 平滑, 而 `cx/cy/rx/ry` 由当帧数据反推, 数据突变→参数突变→位置突变。修复第 1 类问题的同时必然制造第 2 类问题——对准实际 bbox 与参数连续性是两个正交需求, 缺一不可。

## 解决方案
1. 轨道几何对准**内容实际 bbox**(由可见页条目反推 `tightBox`), 缺省回落名义区域; 行高/间距封顶防拉伸。
2. 把轨道参数(cx/cy/rx/ry)从位姿计算中拆成独立目标, 渲染层持有"当前生效参数"并逐帧**帧率无关指数平滑**逼近目标: `k=1-exp(-dt/τ)`(τ≈0.35s); 位姿仍用 `angle=time*ω` 在缓动后的轨道上取值, 位置保持 C0 连续, 观感为"巡游过去"。
3. **snap 兜底**(直接落位不缓动): 首帧 / reducedMotion / dt≤0 或 >0.5s(页签后台恢复) / 目标位移超场景对角线×0.6(手动 seek, 瞬移符合预期)。
4. 派生动画量(如腿摆动速度)用**缓动后位置的实测帧间差分**(与解析速度同量纲 px/s, 勿再乘周期系数), snap 帧回落解析值防尖峰。

## 验证
- 单测(prompt-spider-ui `tests/live-ui.test.mjs`): 缓动单调逼近无过冲、单帧步进上界、`poseFromOrbit(orbitTarget(...))≡livePose` 重构等价。
- 浏览器逐帧实测(测试文档 §17): 首词到达最大相邻帧位移 37.2px(修复前应为 ~250px 一步)、翻页 8.5px、过滤变位 133px 目标约 1s 指数收敛、seek 286px 单帧 snap 后无漂流、布局切换单调收敛无回抽。

## 适用边界与反例
- 适用: 任何"动画几何由当帧数据反推"的场景(Canvas/SVG/游戏实体巡游、图表标注轨道、相机跟随内容包围盒)。
- 反例/不必做: 目标本来就恒定的轨道(缓动恒等, 无代价但也无收益); 用户主动离散操作(seek/跳页首帧)期望即时响应, 应走 snap 而非缓动; 极端 bbox 差异(>0.6 对角线)仍 snap, 未验证超长漂流缓动的观感接受度。
