# nowrap容器内渲染不可控长文本须展示级截断防横向溢出

## 背景 / 现象
观测面板检索流条目把用户检索词原样渲染进 `white-space:nowrap` 的元信息行。一条 1200 字
查询进来后, `#feed` 容器 `scrollWidth=13681px`(`clientWidth=1000`), 整页横向溢出 13.6 米,
正常内容被推到视野外。平时测试用短查询, 该路径长期未暴露。

## 根因
两层机制叠加, 缺一不炸:
1. `white-space:nowrap` 禁止换行, 文本宽度=内容全宽;
2. flex 子项的 `min-width:auto` 默认值使容器不可收缩到 min-content 以下。无空格长串
   (中文长句 / base64 / URL)无法断行, min-content 即整串宽度, 于是 flex 容器整体撑破父级。
关键: 数据源宽度不可控(用户输入), 而展示层假定它可控——只要渲染不可控长文本, 缺陷只是
"还没遇到足够长的数据", 不是"不会发生"。

## 解决方案
展示层截断, 全文留给悬停:
- 渲染前截断(`q.length>24 ? q.slice(0,24)+'…' : q`), 阈值与同文件既有约定对齐;
- 全文写入 `title`, 悬停/辅助技术仍拿得到完整内容;
- 纯 CSS 的 `text-overflow:ellipsis` 需同时给 `overflow:hidden` + 明确宽度或
  `min-width:0`, 在 flex 里易漏; 数据侧截断对布局零假设, 更稳。

## 验证
修复前后各跑一次同一份数据(`docs/tests/2026-10-21-full-coverage-test.md` §25):
- 前: `sw=13682 cw=1000`; 后: `sw=1000 cw=1000`, 页面 `scrollWidth=1078` 无横滚;
- 截断条目 `title` 长度=1200(全文可达), 可见文本以 `…` 收尾。

定位手法(可复用): 页面横向溢出但看不出谁撑的时, 遍历容器内所有元素找
`el.scrollWidth > el.clientWidth + 2`, 一次命中目标元素。

## 适用边界与反例
- 适用于: 任何渲染用户输入/外部数据到 nowrap、定宽表格单元格、单行卡片标题的场景。
- 不需要: 数据源宽度已知有上限(如枚举、日期)时, 直接 nowrap 无妨。
- 反例提醒: 若该行本就设计为多行折行(`white-space:normal` + `overflow-wrap:anywhere`),
  加截断反而丢信息——先确认"单行"是设计意图再截断。
