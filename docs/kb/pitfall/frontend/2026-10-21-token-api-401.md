# 前端多处手拼鉴权 token 参数漂移导致部分 API 静默 401

## 背景

观测面板(`kb serve` 自带 index.html)在 `--token` 团队态下, 用户按引导带 `?token=…` 打开页面, 页面能加载但 KPI/双榜/检索流全空, 且只显示"需要访问令牌"横幅 — 明明 URL 已带 token, 症状极具误导性。

## 根因

token 携带逻辑在同页面内不一致: `/api/callers`、`/api/spider`、SSE stream 的 URL 都拼了 `token=${qs.get('token')}`, 但 `loadStats`(/api/stats)、`loadFeed`(/api/feed)、启动自检(/api/health) 三处 fetch 漏拼。serve 端 `_authorized()` 对 query token 是统一放行的, 所以后端没问题, 是前端各 fetch 各自手写 token 拼接导致漏网。`kb web` 打开团队 URL 时同样触发(launcher 只给页面 URL 附 token, 页面内部 fetch 依赖自身拼接)。

## 修复

彻底方案(二轮已落地): 新增 `apiUrl(path)` 统一注入器, 全部 6 处 fetch + SSE EventSource 收口走它, 禁止手拼; 静态守护测试升级为"fetch/EventSource 的 /api/* 字面量必须经 apiUrl()"(test_stats_serve.py::test_panel_api_requests_use_apiurl)。另给 loadFeed/loadMatrix 补 401 短路, 防 token 中途失效时 401 JSON 被当数组解析抛 TypeError。

## 教训

前端多处手拼同一鉴权参数是漂移温床, 正解是封装统一注入器(apiUrl)而非逐处补参数——逐处补本身又是不一致的新温床; 配"资产级"静态守护测试(此前 tests/ 对 index.html 零覆盖)锁死收口。
