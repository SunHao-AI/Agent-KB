# 自定义可点元素只绑onclick漏键盘三件套成为全屏唯一鼠标专属交互

## 背景 / 现象

观测面板第四十一轮(键盘/无障碍/空态专项)真实浏览器 Tab 遍历: 零命中榜行、
检索流条目、过滤框、回放浮层全部键盘可达(且 Enter/空格/Esc/←→ 行为正确),
唯独联邦矩阵下钻行 `.matrix-link`(tr 绑 `onclick` 切单项目视图)完全不在
Tab 序中——`tr.focus()` 后 `activeElement` 停在 `BODY`, 键盘用户根本无法
触发"下钻"这个联邦视图的核心动作。它是同页**唯一**一个仅鼠标可操作的交互,
其余同行级交互早已做对, 说明这是新加交互时漏了配套, 不是整体缺 a11y。

## 根因

`<tr>`/`<div>` 等非原生可交互元素默认**不在 Tab 序、不可聚焦、不产生
click 键盘事件**。面板里每处行级可点都是手工三件套: `tabindex="0"` +
`role="button"` + `onkeydown`(Enter/空格)。`loadMatrix` 的下钻行是后加的
交互, 只写了 `tr.onclick=...`, 三件套一件没带——"加交互"与"加键盘配套"
是两个动作, 没有机制强制同时发生, 纯靠人记得。

## 解决方案

- 下钻行模板补 `tabindex="0" role="button" aria-label="下钻到项目 …"`,
  绑定处 `onclick`/`onkeydown` 共用同一个 `go()`(M-1 同款: `e.target!==tr`
  直接 return, 防内部元素冒泡双触发)。
- 焦点可见: `:focus-visible` 名单加入 `.matrix-link`(outline-offset 用
  负值, 避免表格行 outline 溢出相邻单元格)。
- 静态守护测试: 扫 index.html, 凡带下钻语义的自定义行模板必须含
  `tabindex=`, 矩阵绑定段必须含 `onkeydown`——把"人记得"变成机器校验。

## 验证

重启 serve 后真实浏览器复验: `withTabindex:2/2`、`withRole:2/2`、
`onkeydown!==null`; 真实 Tab 进入行 → Enter → `view=single&caller=agent-kb`
且横幅提示下钻。回归 `test_panel_custom_clickables_are_keyboard_reachable`
+ 全量 pytest **345 全绿**; ruff F,E9 通过。

## 适用边界与反例

- 原生 `<button>`/`<a href>` 自带键盘语义, 不需要三件套——能用原生就用原生。
- 纯展示性 hover 提示(title/tooltip)不算交互, 无需进 Tab 序, 否则 Tab 序
  被噪音淹没。
- `role="button"` 元素若内含别的可聚焦元素, 键盘处理必须判 `e.target`
  是否行本身(双触发陷阱)。
