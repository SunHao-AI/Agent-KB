# 跨仓搬移只动文件不同步派生索引且目标路径未校验致双向失联

## 背景 / 现象

`kb export` 把项目库条目搬进共享知识库(人工终审动作)。第十四轮走查实测三个洞:
1. **双向失联**: 搬移成功后两仓 `index.jsonl` 都不重建——源仓检索**命中已删除的条目**
   (点开即断链), 目标仓检索**看不到新条目**, 直到有人碰巧手动 `kb index`;
2. **假仓黑洞**: `--to-repo` 路径打错(如 `../Agent-KBB`)时, 旧实现
   `mkdir(parents=True)` 静默建出新目录当目标仓, 完成"搬入+删源"——条目从两仓索引
   双双消失, 命令还打印成功路径(exit 0);
3. **无警示直通**: status=draft/confidence=speculative 的未终审条目原样搬入共享库,
   与"accepted 才能上提"的门控红线精神冲突且零提示。

## 根因

搬移动词只实现了**文件系统层**(write dst + unlink src), 漏了系统的两个不变量:
- 索引是文件的**派生物**, 且检索只读派生物(index.jsonl)不读源文件——凡是"移动/删除/
  新增条目"的写路径都必须让派生物同步, 单仓如此, 跨仓搬移要同时同步**两仓**的派生物;
- "目标不存在就创建"(`parents=True`)对搬移是危险默认: 目标仓路径是**用户输入**,
  打错的后果(数据消失且报成功)远重于报错的代价。

## 解决方案

`export_entry` 三处收紧(搬移仍是人工动作, 故 [3] 警示不拦截):
- 前置校验目标仓 `kb/` 目录必须已存在, 否则 `GateViolation` 拒绝且不删源、不建目录;
- 搬移成功后 `build_indexes()` 重建**源仓与目标仓**双方索引;
- 源条目 `status != accepted` 或 `confidence == speculative` 时 stderr 打
  `kb warning: ... 未终审/未证条目已搬入共享库`。

## 验证

- 端到端: accepted 条目 export 后目标仓 search 命中该 id、源仓 search 不再命中
  (修复前两仓检索结果都停留在搬移前的旧索引);
- 假仓: 指向不存在的 `--to-repo` 报 `target repo has no kb/ dir`, 断言源文件未删、
  假仓目录未被创建;
- 回归 `test_export_rejects_target_repo_without_kb_dir` / `test_export_rebuilds_both_indexes`
  / `test_export_warns_on_unreviewed_entry`, pytest 291 全绿。
- 注意 draft 条目不进检索索引(设计), 验证双向检索要用 accepted 条目, 否则会误判
  "目标仓不可见"。
- §43 变体回归: `test_review_accepted_makes_entry_searchable_immediately` /
  `test_accepted_entry_visible_to_dedup_without_manual_index` /
  `test_set_scope_refreshes_index_scope_field`, MCP 探针复跑 accepted 后即时可检索、
  重复沉淀被去重拦截, pytest 309 全绿。

## 适用边界与反例

适用于一切"移动实体 + 存在派生索引/缓存/搜索面"的跨仓/跨目录搬移(包管理器移包、
CMS 移文章、 monorepo 拆仓)。判据: 每个会改变"哪些文件存在"的操作, 都要问一遍
"依赖这个事实的派生物在哪几个地方, 各自怎么更新"。"目标路径用户输入 + 失败不可逆"
的组合必须前置校验存在性, 而非 mkdir 兜底。反例: 纯新增(不删源)可容忍索引滞后到
下一次例行重建; 跨仓搬移因为有"删源"一半, 滞后会制造两仓各自的悬空引用, 必须原子化
同步。

## 新发现(第二十五轮走查 §43): 同根因的仓内状态流转变体——隐身的是"刚终审的自己"

第十四轮修的是**跨仓搬移**不重建双方索引; 第二十五轮在**仓内状态流转**上找到同一
根因的第二个变体, 且更隐蔽:

`gate.review`(draft→accepted) 与 `gate.set_scope` 只 `_save` 源文件, 不重建本仓
index.jsonl。MCP 端到端探针实测: `kb_create → kb_review(accepted)` 成功、源文件
status 已 accepted, 但 `kb_search` 返回 `hits:[]`("scanned 0")——条目对检索隐身;
更锋利的是**对去重也隐身**(live 池读 index.jsonl, draft 池现算只认 status=draft):
再沉淀同主题条目查重不命中, 同一条知识被**重复沉淀**。

比搬移变体隐蔽三点: ①动词是"流转"不是"移动", 直觉上不涉及索引; ②隐身对象是刚
自己终审通过的条目——红线1 明写"agent 自审 accepted 无需等人工", 承诺的闭环在
最后一步(入检索面)断裂; ③"下一个任务会重复沉淀同一条知识"是间接后果, 单看任何
一步都不报错, 只有跨任务视角才显形。修复: `_reindex(repo)` 挂到 review/set_scope
落地处(repo_name 口径与 cli 一致), 与 export 第十四轮同一先例——但**先例当时只
在 export 注释里记了一句, 没有升华为"所有改 live 池字段的写路径都要重建"的全局
约束**, 于是 review 照样漏。教训: 修 A 处的同类缺陷时, 把判据写进沉淀条目做全仓
普查, 别只修触发的那一处。

判据补强(在原判据"改变哪些文件存在"之外): **"改变派生索引所索引的字段值"同样必须
重建**——status/scope/confidence 都是 index.jsonl 里的列与检索过滤字段, 源文件改了
而索引滞留, 与文件删了而索引滞留是同一类失真。
