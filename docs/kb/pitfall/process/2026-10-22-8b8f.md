# 同一概念两套发现规则: 质量门控与消费链各扫各的, 漂移出免检角落

## 背景 / 现象

kb 工具链里"哪些文件算知识条目"这一概念被实现了 **6 次、两种语义**:
lint 用"kb 根第一层目录再向下、排除点开头目录"(注释写明为避免扫入挂载子仓),
index/gate/query 用 `kb.rglob("*.md")` 全量扫。第二十四轮探针构造 kb 根直下散文件
`kb/loose.md`(front-matter 故意写坏: 非法 type、非法 status、缺 severity)——
**index.jsonl 收录它、可被检索命中消费, lint 却零报错**。同一份数据, 门控与消费链
看见的集合不同, 交集之外的部分就是"进检索但免检"的角落: schema 校验、重复 id、
指纹冲突、占位段检测全部绕过。

## 根因

"条目发现规则"是一个**跨模块共享概念**, 却没有唯一实现——每个调用点就近手写一遍
遍历。两种语义谁都没错(lint 排除点目录是为了不扫挂载外仓, 有其道理), 错在没有
把正确规则收敛成一个函数: 后来者在消费链上任选 rglob 复制粘贴, 与门控侧的窄规则
静默漂移。这是历轮"同概念多实现"家族(§38 恒空指标、§40 猜测外键)的又一变体:
**这次漂移的不是字段值或匹配逻辑, 而是"数据集合的边界"本身**——边界不一致时,
门控声称的"全库已校验"是假命题。

## 解决方案

`kb.entry.iter_entry_paths(repo_root)` 成为条目发现的**唯一事实源**(布局契约:
条目只住 `kb/<type>/...`, 点目录是外仓不进父仓视野), lint/index/gate(查重+`_find`)/
query(待复核+待上提) 六个读源全部改接; 回归测试直接断言"各读源可见集合必须相等"
(结构性防漂移, 而非各处贴注释约定)。

关键配套: 统一后散文件从"进检索免检"翻转为"谁都不看见"——**静默失踪比免检更糟**,
所以 lint 新增 `stray_entry_paths` 检查, kb 根直下带 id 的 .md 显式报错点名
("请移入条目目录"), 两端都堵。

## 验证

探针修复前 `index 收录=[b002, b001, g001] / lint 对坏文件报错数=0`; 修复后
`index 仅收 g001 / loose.md 被 lint 点名`, `.mounted` 外仓维持"不进父仓视野"设计内
语义。回归 test_lint.py +2(散文件点名+排除 / 四读源集合一致性), pytest **306 全绿**;
真实仓(当前恰无散文件)`index --check` 两处无漂移、lint 两处通过。

## 适用边界与反例

适用于任何"质量门控(校验/lint/CI 检查)与消费链(索引/检索/构建)各自枚举数据集合"
的系统: 代码 lint 的 glob 与打包工具的 glob、测试发现规则与 CI 触发规则、schema
校验遍历与迁移工具遍历。**判据: 门控说'全库通过'时, '全库'与消费方加载的集合是否
同一函数算出来的**。若两处枚举由不同人不同期写就, 默认当作已经漂移, 先做集合差分。

反例: 有意为之的宽窄不同(如构建时排除 test 数据)是合理需求, 但必须在代码里显式
声明差异来源(如 `paths = iter_all() - EXCLUDED`), 让差异可审——本缺陷的坏在"无人
声称差异存在过"。
