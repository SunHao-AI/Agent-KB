# 命令行工具把不存在的仓路径报成空结果误导Agent以为库无知识

## 背景 / 现象

`kb` CLI 的 `--repo`/`--agent-kb` 指向不存在的路径时, `search` 返回 `[]` 且 exit 0,
stderr 一片安静。第十五轮走查探针实测: `kb search --repo <拼错的路径>` 与"库里确实
没有这条知识"的输出**逐字节相同**。对以退出码+stdout 做决策的 Agent 消费方, 这等于
把"路径打错"报成"知识库没有答案"——Agent 会据此跳过真实存在的知识、或直接开始
"从零解决"一个已有踩坑记录的问题。

## 根因

搜索面数据源是 `kb/index.jsonl` 的加载函数对"文件不存在"返回 `[]`(为容忍未 index 的
新仓/空仓), CLI 层又从不校验用户显式传入的路径参数。两类语义被压进同一个空结果:
①"仓存在但库里没命中"(正常检索结果), ②"仓根本不存在"(调用方错误)。目录不存在 →
`rglob` 空转 → 空索引 → 空命中, 全程没有任何一步知道"路径是错的"。与"坏文件挡住索引
重建后 search 报库里没有"(kb-20261022-acc8)同属**症状层把故障层伪装成正常空结果**,
只是这次伪装发生在输入解析而非文件解析。

## 解决方案

CLI dispatch 收口处对**用户显式传入**的路径参数统一前置校验:

```python
if args.cmd != "init" and args.repo is not None and not repo.exists():
    print(f"kb error: --repo 路径不存在: {repo}", file=sys.stderr)
    return 1
for p in args.agent_kb or []:
    if not Path(p).exists():
        print(f"kb error: --agent-kb 路径不存在: {p}", file=sys.stderr)
        return 1
```

两个边界: ①只校验"用户显式传了参数"(缺省 `.` 不拦, 未初始化目录另有 doctor 管);
②`init` 豁免——首次接入时 kb 载体目录本来就该允许不存在(由 init_repo 建骨架)。
区分原则: **空结果只有在输入被确认合法时才有意义**, 所以校验放入口, 而不是让各
搜索函数各自猜。

## 验证

- 探针: `search --repo <不存在路径>` 修复前 exit 0 + `[]`; 修复后 exit 1 +
  `kb error: --repo 路径不存在: ...`(stderr 可辨); `--agent-kb` 层路径错误同样拦截;
- 无误伤: 存在但无匹配的目录仍正常返回空 + exit 0;
- 回归 `test_cli_missing_repo_path_errors`, pytest 292 全绿。

## 适用边界与反例

适用于一切"输出供 Agent/脚本消费"的 CLI: 退出码与 stdout 是接口契约, "没找到"必须是
**真实搜索过的结论**, 而非输入错误的副产物。判据: 对每个路径/ID 类参数问一遍"传错了
用户会看到什么"——与正常空态不可区分即为缺陷。反例: 交互式工具可容忍宽松(用户能看见
提示词继续试); "文件不存在→空集合"在**内部**数据加载层仍是正确容忍(新仓未 index),
要收紧的是**边界上的用户输入**, 不是内部分支。
