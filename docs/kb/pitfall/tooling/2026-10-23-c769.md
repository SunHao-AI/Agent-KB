# 手写写读两侧各自为政: 原样嵌入配无脑截断, 凭据静默损坏

## 背景 / 现象

`kb` 的用户级配置 `~/.kb/config.toml` 用手写"最小子集"读写(不引 tomllib 以免
锁死 3.11+, 见 userconf.py 模块头)。第二十九轮走查探针实测两条独立损坏路径:

- **读侧无脑截断**: 写侧恒输出 `key = "值"`, 读侧却对值无条件
  `v.split("#")[0]`——含 `#` 的 URL 片段(`http://kb.internal:4320/#board`)或
  令牌(`a#b#c`)写进去再读出来就被从中间截断。手写带引号配置加行内注释
  (`url = "http://h/x#y" # 注释`)同样截错: 引号内的 `#` 是值, 引号外的才是注释,
  旧实现分不清。
- **写侧原样嵌入**: 值含 `"` 时产出 `token = "a"b"` 这类**损坏文件**(非合法
  TOML), 后续所有读取全坏。

最恶劣的是失败模式: 截断是**静默**的——token 尾巴被吃掉后请求照发, 团队态
收到的是 401, 用户完全无从怀疑到"配置文件里的 # 被注释逻辑吃了"。

## 根因

写侧与读侧是**同一份格式契约的两半**, 却是两个人类心智各写各的: 写侧假设
"值总是原样能放进去", 读侧假设"值里不会有任何需要转义/引号包裹的东西"。
两个假设都没写下来, 谁也没约束谁。这是 D-28 判据(同一事实的多实现必须同源)
在**编解码对**上的形态: 序列化器与反序列化器只要不是从同一份格式规范派生,
每个边界字符(`#`、`"`、`\`)都是一枚静默损坏的地雷。而既有测试只往返过
`http://kb.internal:4320` + `s3cret` 这类"干净值", 恰好绕开全部地雷。

## 解决方案

- **读侧按引号语义解析**: 双引号值用 `r'"((?:[^"\\]|\\.)*)"'` 匹配(闭引号跳过
  转义对 `\"`, 朴素 `find('"')` 会被提前闭合骗过), 闭引号后只允许空白或
  `#` 注释, 其余(`"a"b"` 的尾段 `b"`)视为损坏; 无引号值才把 `#` 起当注释
  (兼容手写)。单引号值取配对闭引号(字面量, 不反转义)。
- **写侧转义 `\` 与 `"`**, 与读侧反转义(单遍 `re.sub(r"\\(.)", ...)`; 两步
  replace 对 `\"` 与 `\\` 交叠会错序误还原)严格互逆。
- **坏文件整体降级为空, 绝不半解析**: 未闭合引号/闭引号后带垃圾 →
  `ValueError` → `read_config` 捕获后返回 `{}`——消费方回退单人态或环境变量,
  好过拿着截断半截凭据去撞 401。旧版写坏的存量文件天然落入此路径。
- 回归 4 个: 含 # 值往返 / 手写引号+行内注释 / 值含引号往返 /
  存量损坏文件降级(test_stats_serve.py +4)。

## 验证

探针修复前后对账: 修复前三例全部往返损坏(`#` 截断 ×2 + 引号写坏文件);
修复后全部保真, 存量损坏文件 `serve_target()` 返回 `(None, None)`。
pytest **321 全绿**(317+4), ruff `--select F,E9` 顺带抓获并清理 stats.py 里
遮蔽 trace.ts_key 导入的逐行相同本地副本(F811, 同族"同源副本迟早漂移")。

## 适用边界与反例

适用于一切"嫌引库麻烦而手写"的 mini 序列化格式(kv 配置、行协议、简单 DSL)。
**判据: 写侧写出的每个字节, 读侧必须有对应的消费规则; 反过来读侧剥掉的每个
字符(注释符/引号/转义), 写侧必须保证不会从值里自发生成**。最省事的自检是
一个往返性质测试: `read(write(v)) == v` 对含全部边界字符
(`# " ' \ = [ ]` + 空格首尾)的值跑一遍。反例: 格式契约有正式解析器
(tomllib/json)兜底时不必手写两侧; 值域已知为纯字母数字令牌时截断缺陷不可
触发——但"已知纯字母数字"必须是**写侧强制**的(校验或转义), 不能是猜测。
