# kb trace 检索埋点查看与回放工作流

观测任意 agent(或人)通过 `kb search` / MCP `kb_search`/`kb_get` 访问知识库的行为:
记录了哪些检索、命中/未命中原因(hit_fields 与死因统计)、返给了什么、agent 实际读了哪些。

## 前提

- Agent-KB 仓已含 `src/kb/trace.py`(≥ commit 3065696)。
- 开启采集(三选一, 默认关闭零开销):
  1. 仓根放置空标记文件 `.kb-trace`(全局持久, 推荐观测期使用);
  2. 环境变量 `KB_TRACE=1`(仅当前进程树);
  3. 单次: `kb search ... --trace`(强制开) / `--no-trace`(强制关, 优先级最高)。
  MCP 侧: 启动参数 `kb.mcp --trace` 或 MCP 服务环境变量 `KB_TRACE=1`。
- trace 落盘: Agent-KB 仓根 `traces/YYYY-MM-DD.jsonl`(gitignore, 只含元数据+摘要, 无正文)。

## 步骤

1. 看调用清单(最新在前):
   ```powershell
   kb trace list                                  # 全部
   kb trace list --caller <仓目录名小写>           # 只看某个 agent 仓
   kb trace list --zero-hit                       # 只看零命中(知识库覆盖缺口信号)
   kb trace list --since 2026-10-15 --limit 50
   ```
2. 看单次检索如何命中: `kb trace show <trace_id>` — 逐层输出 scanned /
   rejected{filter,query} / matched[].hit_fields+hit_spans / returned。
3. 导出动画回放(免手输 id, 自动取最近一次):
   ```powershell
   kb trace export --latest -o replay.json                    # 全部 caller 中最近一次
   kb trace export --latest --caller <name> -o replay.json    # 指定 agent 的最近一次
   ```
4. 在 prompt-spider-ui 中播放: 克隆 `Kirito14IT/prompt-spider-ui`(Node 20+),
   仓根 `node server.mjs`, 页面导入 replay.json。三分支: 项目层命中(绿)/
   通用层命中(红)/已读消费(黄, agent 真的 kb_get 过)。

## 验证

- `kb search --query x --repo .` 跑一次后 `kb trace list` 出现新行;
- `kb trace show` 的 matched 中含 hit_fields(命中字段)与 hit_spans(位置);
- 同 trace 的 kb_get 消费在回放里进"已读消费"分支;
- 删除 `.kb-trace` 且无 env 后, 检索不再产生任何 trace 文件。

## 常见错误

- 列表为空: 开关没开(优先级 CLI > env > 标记文件 > 默认关); 或 `--repo` 指向错根
  (trace 恒集中写 Agent-KB 仓根, 读取端 `kb trace --repo` 可显式指定)。
- caller 名对不上: 统一为 `--repo` 路径 resolve 后目录名小写(可用 `kb.mcp --repo-name` 覆盖)。
- 回放导入报错: record 契约变更, 只改 `src/kb/spider_export.py` 顶部常量区适配, 勿动数据层。
- 想停采集: 删 `.kb-trace` 文件即可, 已有 trace 文件保留可继续查看。
