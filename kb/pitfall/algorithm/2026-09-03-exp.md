# exp 校验散落两处导致宽限期失效

## 背景 / 现象

若在验签器里顺手判 `exp`（PyJWT 默认行为），到期 token 直接验签失败 ⇒ 走"安全类失败 hard expired"路径 ⇒ 宽限期永远进不去，grace 语义整体失效。

## 根因

若在验签器里顺手判 `exp`（PyJWT 默认行为），到期 token 直接验签失败 ⇒ 走"安全类失败 hard expired"路径 ⇒ 宽限期永远进不去，grace 语义整体失效。

## 解决方案

验签器**禁判 exp**（只可选判 `iat`），到期与宽限统一由 `state.py` 判定；测试显式锁定该契约：

```python

def test_verify_never_checks_exp():

    stale = {**CLAIMS, "exp": 1_500_000_000}

    token = _issue(PRIV_B, V2_HEADER, stale)

    assert TokenVerifier({"k2609": PUB_B}, clock=_Clock(1_900_000_000)).verify(token)["exp"] == 1_500_000_000

```

同理，`detect_service.py` 内禁止重新计算 `min()` 到期口径；到期时间唯一出口是 `EngineDecision.effective_expiry`。

## 验证

测试显式锁定该契约：

```python
def test_verify_never_checks_exp():
    stale = {**CLAIMS, "exp": 1_500_000_000}
    token = _issue(PRIV_B, V2_HEADER, stale)
    assert TokenVerifier({"k2609": PUB_B}, clock=_Clock(1_900_000_000)).verify(token)["exp"] == 1_500_000_000
```
