# 两容器共写单调时钟文件互截断 + 原子写 tmp 同名竞态：tmp 名必须全局唯一

## 背景 / 现象

2026-09-25（与 web 仓 `backend/授权三态与离线容器.md` 同名条目配对；两仓时钟类是复制品，同步修复）：两容器共写 `/data/flysee/.clk`，旧实现先截断再写 8 字节，非原子写下并发读者拿到短读即失败；原子写改造后 tmp 名只拼 pid，同名 tmp 被另一实例 `os.replace` 抢走、再 replace 即 ENOENT。

## 根因

两层机制：其一，时钟文件旧实现先截断再写 8 字节，非原子写下并发读者拿到短读即失败，且基准写在容器可写层、随重建清零；其二，原子写改造后 tmp 名只拼 pid，而同进程每个 `LicenseChecker` 各持一个 `MonotonicClock`——同名 tmp 被另一实例 `os.replace` 抢走，再 replace 即 ENOENT。pid 的唯一性粒度是进程，覆盖不到同进程多实例。

## 解决方案

1. 原子写：同目录 tmp + `fsync` + `os.replace`；

2. tmp 名 = `pid + uuid8`（跨进程/同进程多实例都不撞名）+ 类级 `_SAVE_LOCK` 串行化"写 tmp→replace"全程；

3. `_load` 读不足 8 字节按 0 静默降级（不打 WARNING，下次 `now()` 覆盖重写）；

4. 两仓 compose 各挂独立命名卷（`flysee_algo_data`/`flysee_web_data`）→ `/data/flysee`，基准跨重建存活、两进程互不干扰。

## 验证

并发单测见 `tests/test_monotonic_clock_concurrency.py`。

## 适用边界

原子写 tmp 名必须**全局唯一**（pid 不够，同进程多线程共 pid）；"两服务共写同一路径"是设计味道，共享状态文件先问"写方几个"；防回拨/水位线类基准必须落卷。并发单测见 `tests/test_monotonic_clock_concurrency.py`。
