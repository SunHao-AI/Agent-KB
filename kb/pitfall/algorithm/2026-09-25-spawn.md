# 冷启动 81.4s 的大头是驱动级一次性成本, 主进程预热即可让 spawn 子进程免付

## 背景 / 现象

**背景数据**（2026-09-25 测试报告实测, GTX 1660 Ti + TRT 8.6 容器）：冷启动
t0→running 81.4s vs 暖启动 23.0s; 差值中"TRT 反序列化完成 → 首帧推流"占 ~45s,
即 NVENC 驱动会话握手、CUDA kernel 首次加载、cuDNN handle 初始化、torch NMS 冷路径。
**关键判定**：检测任务是 spawn 子进程（SEC-5, 禁 fork）, 主进程 import/模型预热
**不会**传递过去——但上述 45s 属 **GPU driver / 内核驱动层**的一次性成本
(NVML 会话、per-context kernel 镜像、NVENC 编码器会话), **跨进程共享**。因此预热只需
在主进程做驱动级动作, 不需要（也无法）替子进程预热 Python 对象：
```python
# app/__init__.py :: _warmup_gpu(), 挂在 _warmup_heavy_imports 同一 daemon 线程串行执行
x = torch.randn(1, 3, 64, 64, device="cuda"); w = torch.randn(8, 3, 3, 3, device="cuda")
torch.nn.functional.conv2d(x, w)                    # cuDNN handle + conv kernel
import torchvision.ops as _tv_ops
_tv_ops.nms(boxes, scores, 0.5)                     # ultralytics NMS 冷路径
torch.cuda.synchronize()
from app.core.tools import _nvenc_available         # NVENC 驱动握手 + 缓存 _NVENC_OK
_nvenc_available()
```
**实测效果**：GPU 预热 1.3~1.6s + NVENC 握手 0.5~0.7s 换冷启动 `to_running`
**74.4s → 14.8~14.9s**（与暖启动持平）, create→to_running 81.4s → 19.1s。
**注意**：
- 预热全链 `try/except` 仅 WARNING——预热是优化不是启动前置条件, 无 GPU/驱动异常时
  首任务回落原冷路径;
- GPU 段与 NVENC 段各自独立兜底（NVENC 是 ffmpeg 子进程探测, 与 torch 异常互不牵连）;
- 预热线程必须排在重依赖 import 预热**之后**（`import torch` ≠ CUDA 已热）;
- 修复镜像必须带 `--env-file {web 仓}/.env` 重建（compose 变量插值单一事实源）,
  否则 `FLYSEE_WEB_M2M_KEY` 注空, 任务在模型解密处报 `UnlockPasswordError`。

## 根因

冷启动差值的大头是 GPU 驱动/内核层的一次性成本（NVML 会话、CUDA kernel 首次加载、cuDNN handle、NVENC 编码器会话），这类成本按设备/上下文跨进程共享；spawn 子进程不继承主进程的 Python 对象，但继承驱动层状态——主进程预先做驱动级动作（一次 conv2d、一次 nms、NVENC 握手）即可让子进程免付这笔跨进程共享的初始化费。
