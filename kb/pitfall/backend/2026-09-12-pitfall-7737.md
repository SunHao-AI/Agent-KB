# 健康检查白名单不含挂载前缀导致生产 401

## 背景 / 现象

**运行时证据**（Debug Server NDJSON）：请求 `/v1/detect_api/health` 时
`in_whitelist_exact=false, mode=bearer, has_authz_header=false`，且 `health handler 已进入`
日志缺失 —— 401 发生在 FastAPI 依赖阶段（router 级 `dependencies=[Depends(verify_bearer_impl)]`），
handler 根本没执行。

## 根因

`verify_bearer_impl` 的健康检查白名单 `_HEALTH_PATHS = {"/health", "/detect_api/health"}`

用**精确匹配** `path in _HEALTH_PATHS`。但路由经 `app.include_router(v1_router, prefix="/v1")`

挂载后，实际请求路径是 `/v1/detect_api/health`（router 内相对路径 `/detect_api/health` + 挂载前缀 `/v1`），

永远不等于白名单里的裸路径 → `bearer` 模式下健康检查落入 Bearer 校验返回 **401**。

影响面：不只是测试。生产 Dockerfile `HEALTHCHECK` 与 README 均打 `/v1/detect_api/health`，

`mode=bearer`/`hybrid` 部署时健康检查会被打死，容器被判不健康。

## 解决方案

白名单判定容忍挂载前缀，用 `/` + 后缀匹配，同时兼容裸 `/health` 与任意版本前缀：

```python

# app/core/auth_mw.py

_HEALTH_PATHS = {"/health", "/detect_api/health"}

def _is_health_path(path: str) -> bool:

    return any(path == p or path.endswith("/" + p.lstrip("/")) for p in _HEALTH_PATHS)

# verify_bearer_impl 内：

if _is_health_path(path) and settings.auth.allow_none_for_health:

    request.state.user_kind = "unauth"

    return None

```

## 验证

回归：`pytest tests/test_api.py tests/test_auth_mw.py`；裸 `/health` 与
`/v1/detect_api/health` 均放行，非健康路径仍受 Bearer 保护。
