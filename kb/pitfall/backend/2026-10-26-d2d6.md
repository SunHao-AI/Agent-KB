# 给存量请求模型校验器加必填约束把合法空串形态拒掉, 全量回归才暴露

## 背景 / 现象

flysee_video_web 仓图片检测功能开发中, 为 `TaskCreate` 的 type 分支校验器
(`_check_type_fields`)新增 image 分支时, 顺手给 video 分支加了"input/output 均非空"
约束。专项测试全绿, 全量回归 `test_suite_gate.py::TestCreateTaskGate` 两例挂:
期望 409/200 的请求变 422——推流模拟等存量形态 `output: ""` 是合法落库语义。

## 根因

"新类型需要校验"不等于"老类型缺的校验都该补上"。output 空串在存量业务里合法
(推流模拟任务由引擎运行时回填输出地址, 创建时即为空), 校验器收窄是对**存量行为面**
的破坏性变更, 与新增 image 分支无依赖关系, 却混在同一次改动里发布。

## 解决方案

删除 video 分支的 output 非空约束, 只保留 input 非空; docstring 明示
"output 允许空串: 推流模拟等形态落库 output 为空是合法存量语义", 防止后人再"顺手补严"。

## 验证

- `uv run --no-sync pytest tests/test_suite_gate.py -q` 6 passed;
  随后全量 `uv run --no-sync pytest -q` 771 passed 1 skipped。
- 反证: 恢复约束即 2 例 422 != 409/200 复现。

## 适用边界与反例

- 适用于给**共享请求模型**(多类型/多形态复用同一 schema)的 field_validator /
  model_validator 加约束的任何改动; 新增独立分支安全, 收窄既有分支必须先跑全量回归。
- 反例: 全新接口的首版校验器不受此限(无存量行为可破坏), 应按 spec 从严。
- 判别口诀: 该校验是否只对**新类型**必要? 是 → 写进新类型分支; 想对老类型也生效 →
  单独评审 + 盘点存量数据形态。
