# 派生计数用两聚合相减时减数漏过同一过滤条件致窄口径下负数

## 背景 / 现象

Agent-KB 观测面板(Agent-KB 仓 `src/kb/serve.py` 的 `_stats_payload`)给剔噪标注算
"当前口径剔了多少合成事件": `synthetic_count = 全量事件数 − 剔噪后事件数`, 想让标注
与同屏 KPI 严格可对账。窗口=全部时数字正常; 面板新增"聚焦单日"(趋势柱点选)后,
浏览器回归实测该标注显示 **已剔除测试合成事件 -812 条** —— 负数。

## 根因

减法两边过滤不对称: 被减数 `sa` 过了 `caller + since/until` 窗口, 减数 `s`(剔噪后
集合)只过了 `caller`, 没有过窗口。宽窗口下两者覆盖同一段事件, 差值恰好是"窗口内
合成数", 看起来一直正确; 窗口一收窄到单日, 被减数缩到当天几百条而减数仍是全窗口
几千条, 相减直接减穿成负数。

宽口径下"看着对"掩盖了口径不对称——这是派生计数最隐蔽的形态: 数字在开发期常用口径
(全量/大窗口)下永远为正, 只有最窄的边界口径才暴露。

## 解决方案

派生计数写成"两聚合相减"时, 两个操作数必须过**完全相同**的过滤链, 逐一对称:

```python
n_syn_win = ((len(stats.in_window(sa, since, until)) - len(stats.in_window(s, since, until)))
             + (len(stats.in_window(ga, since, until)) - len(stats.in_window(g, since, until))))
```

更稳的写法是不相减、直接数被剔的集合(单一事实源, 结构上不存在不对称); 只有在被减
侧本就必须单独计算(如 raw 口径整体复用)时才用对称相减。配套约束: 任何新增过滤维度
(caller/窗口/raw/视图)落地时, 全仓 grep 这类相减表达式, 确认新维度已同时施加到两边。

## 验证

`Agent-KB` 仓 `tests/test_stats_serve.py::test_serve_stats_reports_dropped_synthetic`
补三条断言: 窗口=今天(`synthetic_count == 3`)、单日聚焦(`since=until=今天` 仍是 3)、
空窗口(`2020-01-01~02` 给 0 而非负数)。旧写法在单日窗口给 4/-1, 新写法 3/0。真实
面板实测: 聚焦 2026-11-01 剔 30 / 2026-10-29 剔 60 / 无事件日 0, 不再出现负数。

## 适用边界与反例

- 适用: 一切"计数 A − 计数 B"推导出的派生指标(剔噪数、增量、留存差、漏斗转化)。
  判据: 两个计数各自还过了什么过滤? 有一处不同即有此风险。
- 反例: 同一查询/聚合内部产生的两数(如同一 SQL 的 `COUNT(*)` 与 `COUNT(x)`)天然
  同口径, 无需此防。
- 姊妹坑: 同一次回归还修了清单弹层"卡上数字与清单条数错位"(取数口径跟视图还是跟
  数字)——同属"两个展示位共享一个口径时, 必须指定谁是事实源"。
