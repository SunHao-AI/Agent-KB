# 硬编码正斜杠前缀比较在路径校验中全线误判穿越，跨平台包含判定须用相对路径计算

> 面向: Agent-KB `TdbmConnector`(消费方) 与 TencentDB-Agent-Memory `MemoryKnowledge`(服务方) 的接入联调。

## 背景 / 现象

Agent-KB 的 `TdbmConnector` 此前只按 `openapi.yaml` 推测契约、从未经真实实例联调(挂账)。2026-10-20 本地起 MemoryKnowledge(Node 22 + tsx + better-sqlite3, LLM_MODE=custom 指向 mock LLM)走完 create→raw/write→ingest→ready 真链路, 暴露三处"按文档写的代码"与真机不符:

1. `POST /wiki/page/read` 按假设发 `{wiki_id, paths:[...]}` → **400**(真契约必填字段是 `refs`);
2. 响应条目按 `it["path"]` 匹配 → 永远取不到内容(真机返回字段是 `ref`, 包在 `data.items[]`);
3. `POST /wiki/search` 的 `data` 里 `results` 与 `links` **都是 list**, "取首个 list"的防御式解析依赖 key 顺序, 有隐患; 且 Windows 服务端返回的 `path` 是 `wiki/entities\uvicorn-sse-reload.md` 混用分隔符, 原样回传 page/read 会解析失败。

另在服务方仓内发现 Windows 可移植性缺陷: `raw/write` 合法文件名一律报 `400 invalid path: traversal detected`。

## 根因

- 服务方路径安全校验用**硬编码正斜杠前缀比较**: `safe.startsWith(base + "/")`, 而 Node `path.resolve()` 在 Windows 返回 `\` 分隔路径, 前缀永远不匹配 → `resolveRawPath`/`resolvePageRef`/`absToPageRef` 全线误判"穿越"。macOS/Linux 容器部署下不可见。
- 消费方按 OpenAPI 文档字面推测字段, 但文档的 `paths`/`path` 假设与实现(`refs`/`ref`)不同步; 且 ingest 产物的 `path` 由服务端 `join()` 拼出, 分隔符随 OS。

## 解决方案

- 服务方(`wiki-service.ts`): 新增 `isWithinDir(base, target)` 用 `path.relative()` + `isAbsolute()` 判定目录包含, 替换三处斜杠前缀比较; `absToPageRef` 改用 `relative()` 并把 `sep` 归一为 `/`。
- 消费方(`sources.py::TdbmConnector`): `_get` 请求体改 `{wiki_id, refs:[id]}`, 匹配字段改 `ref`; `_search` 显式取 `data["results"]`(不再"首个 list"); 两侧对 `native_id` 都做 `replace("\\", "/")` 归一化, 保证 search 命中→get 读取跨平台闭环。

## 验证

真机(本机 8421, wiki `wiki-itvy6erg`, 7 页):
- `search('PermissionError')` → 命中 `source://tdbm/wiki/entities/redis-timeout.md`(score 1.51, path 已归一化); 中文查询 `无鉴权` 经 bigram 分词同样命中;
- `get(hit.id)` → 返回含 `PermissionError` 全文(len 362); 不存在的 ref → `None`(响应 `not_found:true`);
- 修复前同一链路: raw/write 400、page/read 400、get 恒 None。
- Agent-KB 全量回归 `pytest tests -q` → 256 passed(含按真机 schema 重写的 `test_tdbm_search_real_schema` / `test_tdbm_get_uses_refs_and_ref_fields`)。

## 适用边界与反例

- 服务方缺陷仅在 Windows 宿主机直跑时触发; Docker/Linux 部署不受影响(所以 CI 发现不了)。
- `refs`/`ref` 是 MemoryKnowledge v3 现行契约(openapi.yaml `WikiPageReadRequest` 亦如此), 若上游再改需以真机为准。
- 消费方归一化只解决"服务端回传反斜杠 path"的读链路; 若写入类连接器出现, 同样要过 `isWithinDir` 式判定而非字符串前缀。
