# 聚合缓存键漏掉口径参数导致两份结果互串

## 背景 / 现象

Agent-KB 观测面板 serve(`Agent-KB` 仓 `src/kb/serve.py`)给 `/api/stats`、`/api/feed`、
`/api/callers`、`/api/trend` 四个只读口做了 `AggCache`: 按 traces 目录签名缓存聚合结果,
同参数重复请求直接命中。P0-1 加"剔噪口径"(默认剔除测试合成事件)与原始口径
`?raw=1` 后, 面板实测出现: 先请求 `?raw=1`, 紧随其后的**默认口径**请求拿回了 raw 的响应
——检索流整屏跳回含噪声数据, `X-Total-Count` 也跟着错。

## 根因

缓存键只拼了业务过滤维度(`caller` / `since` / `until` / `limit`), 没把**改变计算口径的
开关参数**算进去。同一 traces 签名下"剔噪"与"原始"是两份不同结果, 却共用同一个 key,
后写者覆盖前者、先请求者读到后者的数据。`AggCache` 的失效判据(traces 文件 mtime+size
变化)对"账本没动、只是换了口径参数"完全无感, 因此不会自动失效。

同类形态: `/api/quality` 顶层数字是 `--repos` 联邦**合计**, 面板按"当前视图"决定下钻清单
是否带 `repo=all`, 于是单项目视图出现"卡上 26 / 点开 0 条"——数字与清单同源于不同口径。

## 解决方案

1. **凡改变输出的 query 参数, 一律进缓存键**。本项目四个端点统一追加 `q.get("raw","")`:
   `ck = ("feed", caller, limit, since, until, q.get("raw",""))`。判据是"该参数是否影响
   返回值", 不是"它看起来像不像过滤条件"。
2. **口径开关做成 URL 级、全端点统一**(面板 `RAWQ` 一份拼参尾, stats/feed/callers/trend/
   export 全带), 避免同屏一半剔噪一半原始。
3. **展示数字与其下钻清单必须同一份数据**: 质量五计数改为直接取清单长度
   (`len(rows[kind])`) 而非各自 `sum()`, 清单从同一缓存桶取; 面板下钻是否 `repo=all`
   取决于**卡面数字是否联邦合计**, 而不是当前视图开关。

## 验证

新增回归(`Agent-KB` 仓 `tests/test_stats_serve.py`):
`test_serve_stats_reports_dropped_synthetic` 同时拉两口径并断言 feed 两口径分离;
`test_serve_quality_entries_drill_down` 断言卡面计数 == 清单 `total` == 行数。
两测在补 raw 进键前实测失败(`['syn3','syn2','syn1','real1'] != ['real1']`), 补键后通过;
全量 `pytest -q` 401 passed。

## 适用边界与反例

- 适用于任何"签名失效式"缓存(内容签名 + 键): 键只覆盖显式过滤参数、口径开关游离在外的
  实现, 不限于本项目 serve。
- 反例/别过头: 纯展示层参数(排序、分页样式、字段裁剪若服务端不实现)不必进键, 否则键
  爆炸。判据始终是"服务端输出是否随之改变"。
- 与 `_read()` 统一读侧入口配合才完整: 各端点若各自调 `read_traces` + `denoise`, 键加对了
  也可能因两处判据漂移而不一致。
