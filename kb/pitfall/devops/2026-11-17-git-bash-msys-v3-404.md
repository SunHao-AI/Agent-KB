# Git Bash/MSYS 把环境变量里的 /v3 静默改写成安装目录绝对路径导致服务全线 404

## 背景 / 现象

在 Git Bash 里以命令行环境变量方式启动 MemoryKnowledge(Node/Hono):
`API_PREFIX=/v3 PORT=8424 ... node .../tsx src/server.ts`。服务正常监听 8424,
`/health` 200, 但所有 `/v3/*` 端点一律返回裸 `404 Not Found`(连注册在 api 子应用
前的任何前缀都试了)。同进程内直接 `app.request("/v3/wiki/list")` 却返回 200,
说明路由本身没问题, 出在"前缀值"上。

## 根因

Git Bash 的 MSYS 子系统会对命令行赋值中"看起来像 Unix 绝对路径"的值做 POSIX→Windows
路径转换: `API_PREFIX=/v3` 被改写为 `<MSYS 安装根>/v3`。实测服务内打印:

```
[shim] apiPrefix="D:/cache/.qoder-cn/bin/git/v3" port=8424
```

即环境变量已不是 `/v3` 而是 Git 安装目录下的绝对路径, Hono 挂载点整体错位, 所有业务
端点 404 而挂在 api 之外的 `/health` 不受影响。这类静默改写没有报错, 从 404 表象完全
推不到"环境变量被换过"。

## 解决方案

三选一:

1. **不传该变量**: 本例代码默认值就是 `/v3`, 删掉 `API_PREFIX=/v3` 即可(本次采用);
2. 用 `MSYS_NO_PATHCONV=1 API_PREFIX=/v3 ...` 或 `MSYS2_ARG_CONV_EXCL="*"` 禁用转换;
3. 改由 `.env` 文件/PowerShell/cmd 传值, 不经过 MSYS 命令行。

排查口径: 给服务加一行启动打印(config 值), 凡"进程内逻辑正常、外部全 404/行为诡异"
先怀疑入参被 shell 改写过。

## 验证

同一 shim 进程分别带/不带 `API_PREFIX=/v3` 启动:
带 → `apiPrefix="D:/cache/.qoder-cn/bin/git/v3"`, `/v3/wiki/list` 404;
不带 → `apiPrefix="/v3"`, `/v3/wiki/list` 200 `{"code":0,...}`。

## 适用边界与反例

- 只影响 MSYS 系 shell(Git Bash/MSYS2)里的**命令行赋值**; 值不以 `/` 开头、含空格或
  多段路径(`a/b`)通常不触发转换。
- 位置参数同理受影响的还有 `--prefix=/x` 这类形态; 脚本若跨平台分发, 勿依赖裸 `/x`。
- WSL 无此转换(那是真 POSIX)。
