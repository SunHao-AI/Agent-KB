# 跨仓/跨语言算法契约必须用固定测试向量互验，不能各测各的

## 背景 / 现象

security
2026-09-19（T-14 kid / T-17 canonical_json / T-20 media sign）
**规则**：所有跨仓密码学契约固定「字面量测试向量」两侧硬编码互验：
- kid = PEM 全文（**含结尾 `\n`**）utf-8 sha256 hex 前 16 位（引擎 `trust_anchor.compute_kid` ↔ setting `crypto/rsa.compute_kid`）；
- 租约 `server_signature` = RS256 over `json.dumps(..., sort_keys=True, separators=(",", ":"), ensure_ascii=False)`；
- media sign = HMAC-SHA256(secret, `"{path}:{t}"`) hex，向量 `secret=test123, path=/live/test, t=1758200000 → 954fe31d…8a80`（`media_sign.js` 与 `media_sign.py` 两侧测试各自断言）；
- HMAC 出站签名串 `METHOD\npath\ntimestamp\nnonce\nsha256(body)`（引擎 `hmac_client` ↔ setting `crypto/signature.verify_signature`）。
改任一侧算法必须同 PR 改两侧向量并双侧跑测。

## 根因

各仓只对自家实现做单测，验证的是「自洽」而不是「一致」：分隔符、sort_keys、ensure_ascii、结尾换行这类拼接细节在单侧测试里永远绿，跨仓联调才暴露。契约固定的唯一可靠办法是把同一组字面量测试向量双侧硬编码、各自断言，并强制「改算法必同 PR 改两侧向量、双侧跑测」。

## 验证

固定字面量向量双侧硬编码互验：media sign = HMAC-SHA256(secret, `"{path}:{t}"`) hex，向量 `secret=test123, path=/live/test, t=1758200000 → 954fe31d…8a80`（`media_sign.js` 与 `media_sign.py` 两侧测试各自断言）。
